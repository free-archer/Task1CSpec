# Task1CSpec

Task1CSpec - локальный оркестратор для ведения задач 1С через последовательные спецификации в Codex. Он хранит материалы задачи в `ProjectSpecs`, проводит работу по ролям, переносит завершенные задачи в архив и помогает обновлять проектную документацию.

Подход вдохновлен OpenSpec, но вместо `changes` используются задачи.

## Структура

```text
ProjectSpecs/
  Архив/
  Документация/
  Задачи в работе/
AGENTS.md
.task1cspec/
  AGENTS.md
  .codex-plugin/
  commands/
  skills/
  scripts/
```

## Использование в Codex без установки плагина

Скопируйте `AGENTS.md`, `.task1cspec/` и `ProjectSpecs/` в корень рабочего проекта и запустите Codex из этого корня. Codex автоматически читает корневой `AGENTS.md`, а все подробные правила, шаблоны, команды и скрипты лежат в скрытой папке `.task1cspec/`.

Основной формат команд:

- `TaskStart <номер-задачи>: <название-задачи>`
- `TaskAnalyst <номер-задачи>`
- `TaskArchitect <номер-задачи>`
- `TaskDeveloper <номер-задачи>`
- `TaskTester <номер-задачи>`
- `TaskTechWriter <номер-задачи>`

Русские алиасы:

- `TaskАналитик <номер-задачи>`
- `TaskАрхитектор <номер-задачи>`
- `TaskРазработчик <номер-задачи>`
- `TaskТестировщик <номер-задачи>`
- `TaskТехническийПисатель <номер-задачи>`

Если клиент Codex принимает неизвестные slash-команды как обычный ввод, можно писать старый формат:

- `/TaskStart <номер-задачи>: <название-задачи>`
- `/TaskAnalyst <номер-задачи>`
- `/TaskArchitect <номер-задачи>`
- `/TaskDeveloper <номер-задачи>`
- `/TaskTester <номер-задачи>`
- `/TaskTechWriter <номер-задачи>`

Если slash-команда не отправляется из-за меню Codex, используйте тот же текст без начального `/`.

## Опционально: режим плагина

В `.task1cspec/` оставлен `.codex-plugin/` для совместимости со старым режимом установки плагина. Для локального режима он не обязателен.

Если Codex показывает команды установленного плагина с namespace, используйте такой формат:

```text
/task1cspec:TaskStart RTD-2343: Доработка переключения вызова из ОМ ВнешниеДанные. ТоварныеОперации
```

Манифест плагина находится в `.task1cspec/.codex-plugin/plugin.json`.

## Процесс

1. `TaskStart` находит существующую задачу по номеру или после подтверждения создает новую папку в `ProjectSpecs/Задачи в работе/`.
2. Роли выполняются последовательно: аналитик, архитектор, разработчик, тестировщик, технический писатель.
3. Каждый этап читает уже созданные спецификации, уточняет недостающую информацию, создает свой файл и останавливается на проверку.
4. Код можно менять только после утверждения спецификации `Реализация.md`.
5. На этапе технического писателя проектная документация обновляется до архивации, а перенос задачи в `ProjectSpecs/Архив/` выполняется только после отдельного подтверждения.

## Файлы спецификаций

- `ТехЗадание.md`
- `Архитектура.md`
- `Реализация.md`
- `Тест-кейсы.md`
- `Документация по задаче.md`

## CLI-помощник

Оркестратор содержит небольшой помощник для работы с папками и стартовыми файлами:

```bash
python3 .task1cspec/scripts/task1cspec.py init
python3 .task1cspec/scripts/task1cspec.py start "RTD-2343: Доработка переключения вызова"
python3 .task1cspec/scripts/task1cspec.py status RTD-2343
python3 .task1cspec/scripts/task1cspec.py role Аналитик RTD-2343
python3 .task1cspec/scripts/task1cspec.py archive RTD-2343
```

CLI управляет только структурой папок, статусами и стартовыми файлами. Агент отвечает за вопросы пользователю, чтение предыдущих спецификаций, анализ кода 1С, создание содержательной спецификации и остановку на проверку.
