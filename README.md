# Task1CSpec

Task1CSpec - локальный оркестратор для ведения задач 1С через последовательные спецификации в Codex. Он хранит материалы задачи в `ProjectSpecs`, проводит работу по ролям, переносит завершенные задачи в архив и помогает обновлять проектную документацию.

Подход вдохновлен OpenSpec, но вместо `changes` используются задачи.

## Структура

```text
ProjectSpecs/
  Архив/
  Документация/
  Задачи в работе/
AGENTS.md
.task1cspec/
  AGENTS.md
  .codex-plugin/
  skills/
```

## Использование в Codex без установки плагина

Скопируйте `AGENTS.md`, `.task1cspec/` и `ProjectSpecs/` в корень рабочего проекта и запустите Codex из этого корня. Codex автоматически читает корневой `AGENTS.md`, а все подробные правила, команды и шаблоны лежат в скрытой папке `.task1cspec/`.

Команды локального режима:

- `Начни задачу <номер-задачи>: <название-задачи>`
- `Начни аналитику <номер-задачи> <путь-к-файлу или текст требований>`
- `Начни архитектуру <номер-задачи>`
- `Начни разработку <номер-задачи>` - подготовить спецификацию `Реализация.md`; на этапе согласования реализации после этой же команды перевести задачу в статус `В разработке` и начать менять кодовую базу
- `Начни тестирование <номер-задачи>`
- `Начни документацию <номер-задачи>`

В локальном режиме команды нужно отправлять как обычный текст без начального `/`. Если написать неизвестную slash-команду, клиент Codex может отклонить ввод до того, как сообщение попадет агенту.

Если пользователь отправил ролевую команду без номера задачи, например `Начни документацию`, оркестратор не выбирает задачу сам, а просто спрашивает номер задачи.

## Опционально: режим плагина

В `.task1cspec/` оставлен `.codex-plugin/` для совместимости со старым режимом установки плагина. Пользовательские команды локального режима все равно отправляются обычным текстом без начального `/`.

Манифест плагина находится в `.task1cspec/.codex-plugin/plugin.json`.

## Процесс

1. `Начни задачу` находит существующую задачу по номеру или после подтверждения создает новую папку в `ProjectSpecs/Задачи в работе/` и служебные файлы `Задача.md`, `.task1cspec.json`.
2. `Начни задачу` не создает спецификации этапов и не начинает анализ требований.
3. `Начни аналитику` требует путь к файлу с исходным описанием или текст требований в сообщении. Если источника нет, агент должен спросить его в чате и остановиться.
4. Если в ролевой команде не указан номер задачи, оркестратор запрашивает только номер задачи и ждет ответа.
5. Роли выполняются последовательно: аналитик, архитектор, разработчик, тестировщик, технический писатель.
6. Каждый этап читает уже созданные спецификации, уточняет недостающую информацию в чате, создает свой файл и останавливается на проверку.
7. Вопросы, TODO для пользователя и незакрытые пункты нельзя оставлять в спецификациях.
8. Первый запуск `Начни разработку` создает `Реализация.md`, но не меняет код. На этапе согласования реализации оркестратор ждет повторную команду `Начни разработку <номер-задачи>`.
9. После повторной команды `Начни разработку` оркестратор обновляет служебное состояние задачи: статус меняется на `В разработке`, после чего разрешены изменения в кодовой базе по согласованной реализации.
10. На этапе технического писателя проектная документация обновляется до архивации, а перенос задачи в `ProjectSpecs/Архив/` выполняется только после отдельного подтверждения.

## Файлы спецификаций

- `ТехЗадание.md`
- `Архитектура.md`
- `Реализация.md`
- `Тест-кейсы.md`
- `Документация по задаче.md`

## Работа без интерпретаторов

Task1CSpec не требует Python, Node.js или установки CLI-помощников. Все операции выполняет агент напрямую через файловую систему проекта:

- создает недостающие каталоги `ProjectSpecs`
- ищет задачу по номеру в `Задачи в работе` и `Архив`
- создает папку задачи и служебные файлы после подтверждения
- читает предыдущие спецификации и шаблоны
- создает или обновляет файл текущего этапа
- переносит задачу в архив только после отдельного подтверждения

Для проверки структуры репозитория можно выполнить:

```bash
sh tests/test_task1cspec.sh
```
