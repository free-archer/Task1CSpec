# Task1CSpec

Task1CSpec - локальный оркестратор для ведения задач 1С через последовательные спецификации в Codex. Он хранит материалы задачи в `ProjectSpecs`, проводит работу по ролям, переносит завершенные задачи в архив и помогает обновлять проектную документацию.

Подход вдохновлен OpenSpec, но вместо `changes` используются задачи.

## Структура

```text
ProjectSpecs/
  Архив/
  Документация/
  Задачи в работе/
AGENTS.md
.task1cspec/
  AGENTS.md
  .codex-plugin/
  skills/
  scripts/
```

## Использование в Codex без установки плагина

Скопируйте `AGENTS.md`, `.task1cspec/` и `ProjectSpecs/` в корень рабочего проекта и запустите Codex из этого корня. Codex автоматически читает корневой `AGENTS.md`, а все подробные правила, шаблоны, команды и скрипты лежат в скрытой папке `.task1cspec/`.

Основной формат команд:

- `Начни задачу <номер-задачи>: <название-задачи>`
- `Начни аналитику <номер-задачи> <путь-к-файлу или текст требований>`
- `Начни архитектуру <номер-задачи>`
- `Начни разработку <номер-задачи>`
- `Начни тестирование <номер-задачи>`
- `Начни документацию <номер-задачи>`

В локальном режиме команды нужно отправлять как обычный текст без начального `/`. Если написать неизвестную slash-команду, клиент Codex может отклонить ввод до того, как сообщение попадет агенту.

## Опционально: режим плагина

В `.task1cspec/` оставлен `.codex-plugin/` для совместимости со старым режимом установки плагина. Пользовательские команды локального режима все равно отправляются обычным текстом и начинаются со слова `Начни`.

Манифест плагина находится в `.task1cspec/.codex-plugin/plugin.json`.

## Процесс

1. `Начни задачу` находит существующую задачу по номеру или после подтверждения создает новую папку в `ProjectSpecs/Задачи в работе/` и служебные файлы `Задача.md`, `.task1cspec.json`.
2. `Начни задачу` не создает спецификации этапов и не начинает анализ требований.
3. `Начни аналитику` требует путь к файлу с исходным описанием или текст требований в сообщении. Если источника нет, агент должен спросить его в чате и остановиться.
4. Роли выполняются последовательно: аналитик, архитектор, разработчик, тестировщик, технический писатель.
5. Каждый этап читает уже созданные спецификации, уточняет недостающую информацию в чате, создает свой файл и останавливается на проверку.
6. Вопросы, TODO для пользователя и незакрытые пункты нельзя оставлять в спецификациях.
7. Код можно менять только после утверждения спецификации `Реализация.md`.
8. На этапе технического писателя проектная документация обновляется до архивации, а перенос задачи в `ProjectSpecs/Архив/` выполняется только после отдельного подтверждения.

## Файлы спецификаций

- `ТехЗадание.md`
- `Архитектура.md`
- `Реализация.md`
- `Тест-кейсы.md`
- `Документация по задаче.md`

## CLI-помощник

Оркестратор содержит небольшой помощник для работы с папками и стартовыми файлами:

```bash
python3 .task1cspec/scripts/task1cspec.py init
python3 .task1cspec/scripts/task1cspec.py start "RTD-2343: Доработка переключения вызова"
python3 .task1cspec/scripts/task1cspec.py status RTD-2343
python3 .task1cspec/scripts/task1cspec.py role Аналитик RTD-2343
python3 .task1cspec/scripts/task1cspec.py archive RTD-2343
```

CLI управляет только структурой папок, служебными файлами, статусами и стартовыми файлами спецификаций для этапов. Агент отвечает за интерактивные вопросы пользователю, чтение предыдущих спецификаций, анализ кода 1С, создание содержательной спецификации и остановку на проверку.
